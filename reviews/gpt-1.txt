## 1) Add **Phase 4: Actual Riemann zeros** sooner than later (even minimal)

Right now you’ve built three spectral toy/baseline systems, but you still haven’t run your own stats pipeline on real zeta zeros. That’s the one thing people will immediately ask for.

### What to implement

* Add a new `zeta-zeros` command:

  * **Option A (fastest):** load Odlyzko tabulated zeros from a file (CSV/JSON).
  * **Option B (compute):** use `mpmath` (via Python binding or external script) to compute the first N zeros, store them, reuse.
* Implement **unfolding** properly:

  * Use the Riemann-von Mangoldt counting function (N(T)) to map heights (\gamma_n) to unfolded levels with mean spacing ~1.
* Run your existing `spacing` + (eventually) `spectral rigidity` analysis on the unfolded zeros.

### Output you want

* Histogram + KS statistic vs Wigner surmise (GUE)
* Variance + confidence intervals
* Optional: number variance (\Sigma^2(L)) and/or (\Delta_3(L))

**Why this is #1:** It turns your project from “we reproduced known GUE facts” into “we reproduced the Montgomery–Odlyzko phenomenon with our own pipeline.”

## 2) Improve the **GUE validation** so it stops looking like a coincidence

You now claim “95.46% match confidence.” That’s… not a standard metric. It invites attack.

### What to do

* Replace / supplement the “confidence” score with standard tests:

### Why this matters

It makes your GUE baseline solid enough that when you compare to zeta zeros later, you can say: “Same code path, same metrics.”
